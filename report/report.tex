\title{Automatic Identification of ICD-Codable Medical Information from Clinical Text}

\author{Kyler Cao, Erix Huynh, Kevin Nguyen}

\maketitle

\begin{abstract}
Assigning International Classification of Diseases (ICD) codes to clinical notes is difficult because the relevant evidence is buried in noisy free text and labeled examples are scarce. We study a sentence-level binary classification task that predicts whether a sentence contains ICD-codable clinical information.

To handle the low-data setting, we implement an offline semi-supervised pipeline around a TF-IDF logistic-regression student and teacher-guided pseudo-labeling on unlabeled MIMIC-III sentences~\cite{johnson2016,lee2013}. The current implementation includes threshold-based self-training, explicit gold and pseudo-label weights, per-class pseudo-label caps, and pseudo-label manifests for auditing accepted examples. The training workflow also supports isolated comparison and calibration modes so TF-IDF and Bio\_ClinicalBERT teachers can be evaluated without overwriting one another~\cite{clinicalbert}.

The current codebase is fully offline, applies the same preprocessing during training and prediction, and keeps the deployable classifier lightweight. After running the final comparison and threshold sweeps, the selected final configuration was the thresholded TF-IDF baseline at approximately 0.70. Later ClinicalBERT, SSL, and hybrid-rule experiments were useful diagnostically but did not improve the final model selection~\cite{clinicalbert,lee2013}.
\end{abstract}

\begin{IEEEkeywords}
Clinical NLP, Semi-Supervised Learning, Pseudolabeling, ICD Coding, Text Classification, MIMIC-III, Machine Learning

\section{Introduction}

Assigning International Classification of Diseases (ICD) codes to clinical notes is a fundamental task in healthcare systems, supporting billing, clinical research, and large-scale data analysis. Traditionally, this process is performed manually by trained professionals who review clinical text and determine appropriate codes. This workflow is time-consuming, expensive, and subject to variability across annotators.

Recent advances in natural language processing (NLP) have enabled automated approaches to clinical text classification. In particular, machine learning models can be trained to identify medically relevant information within unstructured text. However, these approaches typically rely on large labeled datasets, which are difficult to obtain in the medical domain due to privacy concerns and the high cost of expert annotation.

In this project, we focus on a simplified but fundamental subproblem: determining whether a sentence from a clinical note contains ICD-codable medical information. This is formulated as a binary classification task, where each sentence is labeled as either \textit{ICD-codable} or \textit{not ICD-codable}. A key challenge in this setting is the extremely limited availability of labeled data, with only 20 annotated examples in the current training file.

To address this limitation, we adopt a semi-supervised learning approach that leverages large-scale unlabeled data from the MIMIC-III dataset~\cite{johnson2016}. We use pseudolabeling to automatically generate additional training data, allowing us to scale from tens of labeled examples to a much larger unlabeled pool~\cite{lee2013}. The current implementation emphasizes conservative pseudo-labeling and linear models because internal validation proved more sensitive to calibration than to model complexity.

We implement an offline TF-IDF logistic-regression baseline, teacher-guided self-training, and an optional frozen embedding branch. The pipeline can compare a TF-IDF teacher against a frozen Bio\_ClinicalBERT teacher under the same SSL regime, then use a separate calibration run to choose the final threshold and ensemble weights~\cite{clinicalbert}. This structure is intended to make the SSL effect measurable rather than hiding it inside a single top-$k$ heuristic.

Overall, this work highlights the importance of data-centric approaches in low-resource clinical NLP tasks and prepares a controlled semi-supervised training setup for the final experiments.

\section{Methods}

\subsection{Overview}

We formulate the task as a binary text classification problem in which each sentence from a clinical note is labeled as either \textit{ICD-codable} or \textit{not ICD-codable}. Due to the extremely limited labeled data (20 examples), we adopt a semi-supervised learning approach that leverages large-scale unlabeled clinical text from the MIMIC-III dataset.

The current codebase is organized as an offline pipeline with the following implemented stages:
\begin{itemize}
    \item sentence extraction and normalization for unlabeled MIMIC text~\cite{johnson2016}
    \item TF-IDF vectorization over word and character n-grams
    \item teacher-guided threshold-based pseudo-labeling with gold/pseudo weighting~\cite{lee2013}
    \item per-class pseudo-label caps and manifest logging
    \item leave-one-out threshold selection on the 20 labeled examples
    \item isolated compare and calibration modes for the Grace SLURM workflow
\end{itemize}

\subsection{Pseudolabeling Strategy}

We first train a baseline classifier using the available gold-labeled dataset. This model is then used to assign pseudolabels to unlabeled sentences extracted from the MIMIC-III corpus~\cite{johnson2016,lee2013}.

In the current main path, we use conservative threshold-based self-training:
\begin{itemize}
    \item 1--2 self-training rounds
    \item high positive and negative confidence thresholds
    \item explicit gold-weight and pseudo-weight settings
    \item per-class pseudo-label caps per round
    \item a per-run pseudo-label manifest that records accepted rows, scores, and sources
\end{itemize}

This keeps the method simple and reduces the chance that noisy pseudo-labels dominate the 20 gold examples. The top-$k$ rank-based path still exists for smoke tests, but the batch workflow uses threshold-based SSL as the default.

\subsection{Model Architectures}

We evaluate two practical model families and one optional branch.

\subsubsection{Logistic Regression}
We use a TF-IDF representation of text as input to a logistic regression classifier. This model serves as both a baseline and a final deployment candidate due to its strong performance in low-resource settings.

\subsubsection{Self-Training Variant}
We retrain the TF-IDF model after adding conservative pseudo-labels from the unlabeled MIMIC pool. The SSL teacher can be either a TF-IDF classifier or a frozen Bio\_ClinicalBERT encoder, but the student remains a lightweight TF-IDF logistic model. The workflow is structured to compare teachers under the same student setup and then calibrate the chosen configuration.

\subsubsection{Optional Embedding Branch}
We also implemented a frozen Bio\_ClinicalBERT embedding model with a logistic-regression head~\cite{clinicalbert}. This branch remains in the codebase both as an optional ensemble component and as a teacher for SSL pseudo-label generation. Whether it is kept in the final ensemble depends on the comparison and calibration runs.

\subsection{Training Procedure}

All models are trained in an offline setting with a maximum input length of 128 words per sentence. The implemented pipeline is as follows:

\begin{enumerate}
    \item Extract and normalize candidate sentences from MIMIC-III notes
    \item Train a teacher-guided TF-IDF self-training student on the unlabeled pool
    \item Log accepted pseudo-labels to a per-run manifest
    \item Compare TF-IDF-teacher and Bio\_ClinicalBERT-teacher runs under the same SSL settings
    \item Run a narrower calibration sweep on the selected teacher
    \item Select a single global threshold using leave-one-out validation
    \item Predict the three inference files offline
\end{enumerate}

The implementation also normalizes prediction text with the same vectorizer settings used during training, which avoids a train/test mismatch that previously hurt performance.

\section{Experimental Results}

\subsection{Experimental Setup}

We will evaluate multiple model configurations to study the effect of teacher choice, data scale, and calibration. The training set contains 20 labeled examples, balanced between positive and negative labels. The inference inputs contain 79 rows for test01, 7134 rows for test02, and 168 rows for test03. The unlabeled MIMIC pool is expanded into sentence candidates for self-training and filtered before pseudo-label selection.

The Grace batch script used isolated per-job output directories. Compare jobs kept the final threshold fixed while contrasting TF-IDF and Bio\_ClinicalBERT teachers; calibration jobs swept a narrower linear-model grid. This avoided output collisions and made it possible to inspect pseudo-label manifests, training summaries, and predictions from each run separately.

\subsection{Comparisons Run}

The final experiments compared the following configurations:
\begin{itemize}
    \item supervised TF-IDF logistic regression without pseudo-labels
    \item threshold-based TF-IDF self-training with a TF-IDF teacher
    \item threshold-based TF-IDF self-training with a frozen Bio\_ClinicalBERT teacher
    \item optional weighted ensemble of baseline, SSL, and embedding components
    \item calibrated global threshold selected by leave-one-out validation
\end{itemize}

The saved bundle also stores vectorizer, logistic, and SSL configuration metadata so that prediction uses the same preprocessing as training.

\subsection{Why the SSL Branch Failed}

The semi-supervised branch was designed to be conservative, but in the final compare runs it became too conservative. The acceptance thresholds were high enough that the teacher never produced confident pseudo-labels, so the SSL loop accepted zero examples. This meant the SSL component contributed almost no new supervision and effectively collapsed back to supervised training.

This failure mode is important because it explains why more engineering around the pseudo-label loop did not produce better validation behavior. The issue was not simply that the code was incorrect. Instead, the candidate funnel, teacher confidence, and gold-label size were mismatched:
\begin{itemize}
    \item the teacher was trained on only 20 labeled rows
    \item the confidence thresholds were high
    \item the unlabeled candidate pool was large and noisy
    \item the final ensemble still had to make decisions from very weak signals
\end{itemize}

As a result, SSL was not harmful in every internal experiment, but it was not strong enough to move the final model above the baseline thresholded model.

\subsection{Threshold Sweep Details}

We also ran a narrow threshold sweep on the baseline model to understand how sensitive the final decision rule was. Lowering the threshold increased recall and produced more positives on the inference files, but the corresponding internal validation quality was not sufficient. Raising the threshold made the model overly selective, which pushed the predictions toward zero and hurt recall.

The best reproduced sweep result on the 20 gold examples came from a threshold around 0.70, which is why that value became the final choice. Thresholds around 0.60--0.62 were explored as a backup, but they traded away too much of the model's agreement with the labeled set and were not competitive.

\section{Discussion}

The implementation is designed around the assumption that this task is dominated by calibration and data quality, not model depth. With only 20 labeled examples, a large neural model would be easy to overfit. The current pipeline therefore prioritizes a conservative TF-IDF plus self-training configuration with explicit caps and gold-weight control.

The most likely risks are noisy pseudo-labels, unstable validation estimates, and over-triggering on generic clinical language. The implementation addresses these risks by logging accepted pseudo-labels, limiting pseudo-label volume per class, weighting gold examples more heavily than pseudo-labeled examples, and using one global threshold rather than per-file decision rules.

Another practical finding is that preprocessing consistency matters. Normalizing text during both training and prediction avoids a feature mismatch that can silently depress performance. The same applies operationally on Grace: per-job run directories and stage logging are now required so that compare and calibration jobs can be inspected independently.

The main limitation is that final training and inference have not yet finished, so the report cannot yet make claims about final model quality. After the runs complete, this section should be revised to discuss which teacher was selected, whether pseudo-labeling improved validation behavior, and what error patterns remain in the debug prediction files.

The final runs did finish, and they showed that the baseline-only TF-IDF model was the most reliable final model path. SSL remained effectively empty under the conservative confidence thresholds used in the compare jobs, and the embedding branch did not beat the baseline once thresholding and inference behavior were taken into account. The best reproducible result remained the baseline thresholded model at about 0.70.

The baseline result was not the strongest model we ever trained, but it was the strongest model we could reproduce consistently at final evaluation time. That distinction mattered because several higher-complexity variants looked promising in local checks but did not hold up once the exact inference files were compared. The final model therefore reflects the most defensible path rather than the most elaborate one.

Another takeaway is that the project benefited from disciplined comparison infrastructure even though most of the advanced variants were ultimately discarded. The isolated run directories, pseudo-label manifests, and comparable teacher settings made it possible to identify the failure mode of the SSL path quickly instead of repeatedly overwriting results and guessing.

In hindsight, the strongest improvement to the overall system would have been to spend more time on candidate funnel design and less time on late-stage rule tuning. The experiments suggest that the model family itself was not the main bottleneck; the bottleneck was how much useful signal could be extracted from the unlabeled pool without overfitting or collapsing recall.

\section{Conclusion}

The final selected model was the TF-IDF + logistic baseline with a single global threshold. After trying SSL, Bio\_ClinicalBERT, weighted ensembles, and deterministic rule layers, the best reproducible result still came from the plain thresholded baseline. The strongest final configuration used a threshold around 0.70.

Pseudo-labeling was useful as an engineering experiment, but it did not produce enough confident labels to improve the final model under the time limit. The Bio\_ClinicalBERT branch likewise helped in internal comparisons, but not enough to replace the baseline. The most important future improvement would be to revisit the unlabeled-data pipeline with a better candidate funnel and less conservative acceptance policy, then re-evaluate the teacher/ensemble design from scratch.
